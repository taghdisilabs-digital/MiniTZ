## Objective
Turn existing runtime state and controls into real player-facing UI/settings. Every exposed option must change the subsystem it names; no placeholder menu entries. Exact shipping language/device/accessibility catalogs remain unapproved and are not invented.

## Existing reusable runtime
- HUD: `BiellaGameplayHUD.h/.cpp`, `BiellaGameplayHUDTest.cpp`, `BiellaTerminalOverlayTest.cpp`.
- Enhanced Input: `BiellaGamesCharacter.cpp`; current look multipliers are `0.8` yaw and `0.6` pitch and mappings are created in `EnsureInputActions()`.
- Game state/modes: `BiellaGamesGameState.*`, restart/failure/terminal tests.
- Rendering baseline currently disables motion blur in production presentation validation.

## Authorized project-local names
- `UBiellaGameUserSettings : UGameUserSettings` — persistent user/settings owner, separate from save/world state.
- `UBiellaSettingsWidget : UUserWidget` — runtime settings surface.
- `EBiellaSessionMode` / `UBiellaSessionStateSubsystem` — only if current GameMode/GameState cannot cleanly own FrontEnd/Gameplay/Pause/Cinematic/Failure transitions; do not create duplicate mode authority.
- `Content/UI/ST_BiellaRuntime` — structured runtime text source/string table or UE-equivalent localization source.

## Minimum concrete settings — no naming gate
Implement and validate these because they map directly to existing behavior:
1. Look sensitivity X/Y replacing hard-coded `0.8/0.6`, with bounded valid ranges.
2. Invert-Y input option applied to live camera pitch.
3. Motion-blur comfort option applied to the actual renderer, defaulting to the current accepted presentation baseline (off).
4. HUD scale/readability option applied to the actual runtime HUD.
These are a minimal implementation set, not the final shipping accessibility catalog.

## Localization validation without inventing supported languages
Use English source text plus an explicitly labeled pseudo-localization/test dataset. This proves key resolution, expansion/layout handling and missing-key behavior without claiming a second supported shipping language. Move player-facing HUD/terminal strings to structured localization keys where practical.

## Pause/session behavior
Add a real pause/settings transition (for example `Escape`) with explicit input/cursor/simulation/UI ownership. Returning to gameplay must restore valid control without stale fire/movement input. Repeated pause/unpause must be idempotent.

## Evidence required
- Runtime HUD bound to authoritative health/ammo/objective/mode state.
- Live before/after proof for sensitivity/invert-Y and one presentation setting.
- Settings persistence/reconstruction across process or game-session reload according to `UGameUserSettings` scope.
- Pseudo-localization expansion + missing-key negative case.
- Accessibility/readability enabled/disabled comparison from live gameplay.
- Pause -> settings -> gameplay transition with valid ownership and no stale controls.
