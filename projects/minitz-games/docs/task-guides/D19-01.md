## Objective
Use packaged-runtime telemetry and accepted product intent to replace only the hardware-tier UNKNOWNs that can now be decided.

## Required deliverable
Updated technical decision entries for measured target hardware tiers or explicit retained UNKNOWNs where evidence is insufficient.

## Validation contract
Each accepted value has measured evidence and current delegated authority; no CPU/GPU/RAM/VRAM target is inferred from installed hardware alone.

## Required evidence
Decision diff, exact telemetry source identities, source commit/tree and task-derived calculation/selection evidence.

## Execution law
- `docs/PRODUCTION.md` owns order/status. This is current task input; historical `FUTURE_BLOCKED`/activation-guard language is inactive.
- Read the smallest current source/evidence set that directly supports the decision. Reuse accepted D07/D17/package telemetry when material identities match; do not rerun broad qualification merely because this task started.
- Perform deterministic calculations/indexing locally when sufficient. A model, screenshot, installed device, or vendor recommendation is not measurement evidence.
- Do not invent target numbers to force closure. Where the objective explicitly permits retained `UNKNOWN`, retain it with the exact missing evidence boundary and continue every independent deliverable.
- Publication transport is nonblocking and uses the existing controller cursor.

## Autonomous execution and blocker handling
`EXECUTOR_OWNS_ROUTINE_BLOCKER_RESOLUTION`: routine implementation, dependency, local tooling, environment, benchmark, telemetry-processing and reversible resource-setup blockers are executor work. Resolve them directly with existing authorized Resources and the smallest affected change; do not create an owner handoff for setup work.

`NO_UNCHANGED_BLOCKER_RETRY`: once an unavailable measurement/resource boundary is recorded, do not rediscover it in repeated strong-model turns. Reuse that evidence, produce the remaining runnable evidence, or let `RESOURCE_BLOCKER_PROGRESSIVE_ROUTING` preserve the task/session while independent canonical work continues.

`NO_REVIEW_OR_APPROVAL_WAIT`: no routine review meeting, sign-off or approval pause exists. Escalate only a genuinely new product decision, unavailable credential/entitlement, or authority for a new paid/external Resource.

`PRESERVE_REAL_ACCEPTANCE`: accepted numeric decisions require real representative measurements and exact identities. Blocker removal may not lower the evidence bar, substitute installed hardware for target evidence, or turn generated/display frames into native performance.
