# 59 — Document Search, Index & Retrieval

## Purpose
A project-scoped search and retrieval workspace for Markdown, TXT, JSON, documentation, specs, notes, and code-adjacent technical text.

## Required detailed content
1. **Search/query bar** — literal, regex, semantic, and hybrid modes.
2. **Scope filters** — project, folder, file type, revision, tag, date, author, and memory class.
3. **Ranked results** — path, section, snippet, score, freshness, source identity, and status.
4. **Match explanation** — lexical match, semantic similarity, metadata match, reranking score, and selected filters.
5. **Source preview** — highlighted matches with surrounding context and exact line/section location.
6. **Index health** — document count, chunk count, index/model identity, build timestamp, stale sources, and failures.
7. **Query history** — saved searches with reproducible parameters and result counts.
8. **Provenance chain** — result → chunk/object → source file → revision/digest → project scope.
9. **Exclusion controls** — quarantine/historical evidence explicitly excluded from normal retrieval.
10. **Context receipt builder** — selected evidence, ordering, token size, and exact references.
11. **Broken/stale source warnings** — missing file, changed digest, superseded revision, or inaccessible source.
12. **Export evidence bundle** — selected results and source manifest for a task/run.

## BIELLA VISUAL LOCK
Transparent background. Deep graphite/navy. Violet primary. Cyan secondary. Green/amber/red semantic state only. Dense information-retrieval UI, thin borders, restrained bloom.

## Acceptance
Normal retrieval cannot silently include quarantined historical material, and every result is source-traceable and revision-aware.
