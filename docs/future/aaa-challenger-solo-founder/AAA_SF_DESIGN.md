## Global execution rules

1. **Activation:** no `AAA-SF-*` task may become active until `AAA-SF-001` proves every then-authoritative predecessor program is durably closed.
2. **One active task by default:** execute tasks numerically. Parallel execution is allowed only when current dependency, side-effect, and Resource state prove independence; never advance merely because a worker is idle.
3. **Current truth wins:** latest owner instruction -> current accepted Project source -> current repository/runtime evidence -> current canonical Drive -> accepted artifacts -> historical/reference -> inference.
4. **Project boundary:** Biella Games tasks modify Games project source only. Biella Engine tasks modify reusable Engine mechanisms only. Cross-project coordination tasks package evidence and must not create a second scheduler, memory, router, object store, model layer, or validation framework.
5. **No drift by implementation guess:** each task reobserves only the exact current interfaces/decisions it needs. Existing semantic equivalents are reused. `UNKNOWN` remains `UNKNOWN` until accepted evidence/authority resolves it.
6. **No fake AAA proof:** screenshots, generated images, cinematics, configs, plans, benchmarks without gameplay, and agent claims are supporting evidence only. Gameplay proof requires real editable source plus running packaged/runtime behavior.
7. **No unnecessary rework:** reuse valid predecessor outputs. Rebuild/rerun only when material input changed, artifact is missing/corrupt, current validation fails, or newer authority supersedes the result.
8. **Evidence per task:** source changes require exact source identity + task-derived validation. Package tasks require exact package identity/digest + clean runtime. Publication requires remote identity/readback.
9. **No permanent reviewer bureaucracy:** validation is task-specific; there is no universal manager/critic/repair chain and no fixed repair count.
10. **Durability:** meaningful source, artifacts, measurements, and closure records must survive process/session/model/worker changes.
11. **Raw history firewall:** MiniTZ/raw historical material remains inactive unless separately processed under the Engine migration firewall; no AAA-SF task may use raw history as active project authority.
12. **Stop boundary:** after closing one task, persist its evidence and activate only the next task allowed by the dependency chain.
