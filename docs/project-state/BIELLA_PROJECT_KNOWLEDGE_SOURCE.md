# Biella Engine — Canonical Project Knowledge Source

## Stable knowledge

Biella Engine is a project-neutral universal AI production/execution engine. Mahdi Taghdisi is final authority for product direction, priorities, architecture decisions, infrastructure use, acceptance, and work policy.

### Durable kernel

Project, Task, Run, Capability, Graph, Node, Artifact, Resource, Event, Knowledge.

Provider, model, tool, GPU, cloud, browser, database, game engine, DCC, renderer and deployment environment are replaceable implementations or Resource state.

### Direct execution

Inspect only task-relevant current state, continue valid work, execute clear requests directly, diagnose failures from real output, repair the smallest affected boundary, preserve unrelated work, and do not substitute planning or governance for execution.

### No artificial blockers or hard QA

No universal approval/readiness gates, mandatory critic/validator chains, fixed repair counts, arbitrary qualification periods, global reviewer requirements, phase gates, or forced prompt-stop boundaries. Real dependencies and constraints apply only where technically relevant. Validation is proportional to the result being claimed.

### Productive legacy-source reuse

Legacy projects/archives are donor sources only. Preserve productive working software/source, algorithms, engineering techniques, technical knowledge, production pipelines/recipes, tooling/automation, execution/recovery logic, benchmarks/failure lessons, productive agent/specialist patterns, and useful project-specific material inside the correct Project.

Remove project identity/branding/lore, permanent management hierarchy, blocker/governance layers, mandatory hard-QA stages, arbitrary limits, stale infrastructure/provider/hardware assumptions, fake capability claims, and nonproductive duplicates/drift.

Productive donor material may be reused directly when already clean and compatible, or adapted when project coupling must be removed. Classification/quarantine is optional compatibility machinery when technically useful, not a universal admission gate.

### Project isolation

Project-specific requirements, source, assets, brand, visual/content canon, preferences, project rules, acceptance, destinations, memory and outputs stay Project-scoped. Project facts do not silently become Engine defaults.

### Tasks, Runs, Graphs, Nodes and Agents

A Task expresses desired outcome and relevant constraints without hardcoding worker/provider topology. A Run is durable execution lineage. A Graph is immutable per revision; replanning creates a new revision. Independent Nodes may run concurrently when dependencies, side effects and Resources permit. Agents/specialists are dynamic execution resources or patterns, not permanent authority hierarchy.

### Resource model

Hardware/software availability is runtime state. Missing hardware changes routing, concurrency, latency, model size or implementation choice; it does not remove semantic Capability.

### Artifact and memory model

Artifact != ContentRef != StorageLocation. Exact bytes may use cryptographic identity when useful for durability, deduplication, provenance, corruption detection, transfer or recovery.

Keep Engine Memory, Project Memory, Run Memory, Historical Evidence and Cache conceptually separate. Cache is rebuildable acceleration, never sole authority. Project-specific knowledge remains Project-scoped; Engine Knowledge is reusable and project-neutral.

### Production intelligence

Reusable creation intelligence may include capability knowledge, logic primitives, generation instructions, production recipes and productive implementation patterns. Project brand, visual canon, content canon and asset references remain Project-scoped.

### Continuity

Default flow: inspect needed current state -> execute smallest useful correct change -> verify the claimed result as needed -> persist meaningful source/artifacts/state -> continue dependency-safe productive work.

Numbered prompts and phases are technical navigation/work units, not universal stop, approval, readiness or qualification gates.
